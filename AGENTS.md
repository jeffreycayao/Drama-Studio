# Agent Notes

- The product/app is called Drama Studio™. Use "Drama Studio™" on brand surfaces (window title, splash, welcome hero, wordmark) and plain "Drama Studio" in running text. Never use the upstream project's name or ComfyStudio in user-facing text, MCP metadata, docs, or chat. The only intended mention of the upstream name is the GPL fork attribution in the README license section.
- `comfystudio` may still appear as a legacy package name, protocol/file-extension namespace, bridge identifier, repository URL, or backward-compatible MCP alias. Treat those as internal compatibility identifiers only.
- Legacy compatibility code may still recognize the upstream name so older data keeps working: workflow marker titles, ComfyUI output filename prefixes, old MCP tool names, the RIFE runtime build marker, the old `%APPDATA%` folder (moved on first launch), saved theme ids and localStorage keys (migrated on startup by `src/services/legacyStorageMigration.js`). Keep those aliases; do not add new ones.
- The project is disconnected from the upstream repository. Its own repository is the private `jeffreycayao/Drama-Studio` on GitHub. Do not add links, endpoints, downloads or feedback routes that point at the upstream project's GitHub organization, website or feedback worker. Public links live in `src/config/projectInfo.js` (Discord `https://discord.gg/5nAZVQ7K4`, website `http://jepoy.dev/`).
- Versioning is `major.minor.patch`, managed by `scripts/bump-version.cjs`: every `npm run build` bumps the patch (skipped on CI or with `DS_SKIP_VERSION_BUMP=1`); use `npm run version:minor|major` for bigger releases. Add user-facing notes under `## [Unreleased]` in `CHANGELOG.md`. Do not hand-edit the version in `package.json`.
- Visual identity: warm charcoal surfaces (`#27231B` family), cream text (`#F6F1E6`), one electric-lime accent (`#D5FA00`), olive (`#687323`) for quiet decoration. Text on solid lime is always charcoal. Use the `sf-*` theme tokens, not raw colors.
- Read `docs/AI_PROJECT_CONTEXT.md` before substantial implementation work.
- Read `docs/AI_CURRENT_HANDOFF.md` for the current branch, migration, and verification state.
- Read `docs/AI_RELEASE_HANDOFF.md` before commits, tags, releases, or GitHub Actions work.
- Drama Studio is a creator-facing desktop video editor. Preserve simple guided workflows; do not turn routine product surfaces into ComfyUI-style node configuration.
- Keep project files portable. Store project-owned media paths relative to the project when possible and preserve legacy project compatibility.
- Treat generation and editing as separate layers: editing, captions, and export must not require ComfyUI unless the specific feature is explicitly a ComfyUI workflow.
- Exception (product decisions, 2026-10-16 and 2026-10-17): `src/components/ComfySetupGate.jsx` runs on first launch until ComfyUI is found (`electron/comfyAutoDetect.cjs`), located or connected, **or** the user picks **Continue without ComfyUI** ("cloud only", saved as `comfySetup.via = 'cloud-only'`, rules in `src/utils/comfySetupGateFlow.mjs`). In cloud-only mode, features that need ComfyUI call `ensureComfyFor(feature)` (`src/stores/comfySetupStore.js`), which shows `ComfyRequired.jsx` and can re-open the gate over the running app; the Generate and ComfyUI tabs show `ComfyRequiredPanel`. Any new ComfyUI-backed entry point must use that guard. Keep the editing code itself ComfyUI-independent; do not remove the gate without the owner's say-so. `DS_SKIP_COMFY_GATE=1` skips it (CI, store certification); `DS_COMFY_GATE_FORCE=1` shows it on a machine that has ComfyUI.
- Agent write actions should inspect first, preview when supported, and use Drama Studio's existing undo/checkpoint paths.
- Keep changes narrowly scoped and test risky behavior at the renderer, Electron IPC, and packaged-platform boundaries it touches.
